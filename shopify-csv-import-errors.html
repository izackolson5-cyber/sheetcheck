Shopify CSV import errors: what they mean and how to fix them

Shopify CSV import problems come in two kinds. The loud kind: the import refuses your file and shows an error. The quiet kind: the import succeeds and breaks products you didn't mean to touch. The loud kind wastes an hour. The quiet kind wastes a week. Here's how to fix both.

The loud errors: when Shopify rejects the file

When an import fails outright, the cause is almost always structure rather than content:

Encoding. Shopify expects the file as UTF-8. Excel on Windows often saves CSVs in a local encoding instead, which produces garbled characters or an unreadable file. In Excel, choose "CSV UTF-8 (Comma delimited)" when saving, or run the file through a text editor and save as UTF-8.

Column names. Shopify matches columns by their exact header names - "Variant Price" works, "Price" or "variant_price" does not. One renamed header and the whole column is silently ignored or the import errors out.

Commas inside cells. A comma inside a value (a description, an address, a European-style price like 19,99) needs the whole value wrapped in quotes. Unquoted, it shifts every column in that row one place to the right and the row is rejected or misread.

Rule: a rejected import is a formatting problem in the file, not a Shopify problem - fix the file, not the store.

The quiet errors: when the import "works"

These are the ones that hurt, because nothing tells you they happened:

Deleted variants. Shopify's own documentation warns that importing a file with a variant-related column but without the option columns can delete existing variant data. A supplier sheet with one row per SKU and no option columns, imported over an existing product, can wipe its Size/Colour variants. The six errors guide covers this with examples.

Blank overwrites. With "Overwrite existing products that have the same handle" selected, a blank non-required cell in your file overwrites the existing value with blank. Empty cells are not "leave unchanged".

Quiet price and stock changes. A supplier file that raised a cost or zeroed a stock level carries that change straight into the live store if you import without comparing it against a current export first.

Excel-mangled data. Excel strips leading zeros from EAN barcodes and turns TRUE/FALSE columns into "yes" or "1", while Shopify's format expects true or false. The full list of these is short and worth reading once.

Rule: every quiet error is caught the same way - compare the file against a current Shopify export before you import, and test with one complete product first.

The five-minute pre-import routine

1. Export your current products from Shopify (Products → Export) so you have a baseline and a backup.
2. Check the incoming file's headers against Shopify's exact column names.
3. Compare the file against the export: which prices, stock levels and variants would change, and do you mean for them to?
4. Import one complete product - all its rows, including variant and image rows - and check the result in the admin.
5. Only then import the rest.
