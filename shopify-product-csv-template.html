Shopify product CSV template: every column that matters, explained

Shopify publishes a blank product CSV template, and almost everyone who opens it has the same two reactions: "why are there fifty columns" and "why does one product take up six rows". Here's the structure behind it, the columns you'll actually use, and a better starting point than the blank template.

Why one product takes multiple rows

The file is flat, but products aren't. Every row with the same Handle belongs to the same product. The first row carries the product-level details (title, description, vendor, tags); the rows underneath it carry its variants (one row each) and its images (one row each). A T-shirt in three sizes with two photos is five rows under one handle. Get the grouping wrong - a variant row under the wrong handle, an option value missing on one row - and Shopify either rejects the rows or quietly deletes the variants it can't match. Shopify's own documentation warns that changing or omitting option data on import can delete existing variant data.

The columns you'll actually fill in

Handle - the product's URL name and the glue that groups its rows. Lowercase, dashes, no spaces. Changing a handle changes the product's URL, so old links break.
Title - required only on the product's first row.
Body (HTML) - the description. HTML is allowed; wrap the whole cell in quotes if it contains commas or line breaks.
Vendor / Product Category / Type / Tags - organisation columns. Tags are comma-separated inside one quoted cell.
Option1 Name / Option1 Value (and Option2, Option3) - how variants exist at all. "Size" / "Large". Every variant row needs them.
Variant SKU - your stock-keeping code. Keep it unique across the whole file.
Variant Price - digits and a decimal point only. No currency symbol, no comma: 19.99, not "NZD 19.99" or "19,99".
Variant Compare At Price - the crossed-out "was" price. Leave blank if you're not running a visible markdown.
Variant Inventory Qty - a whole number. An inventory column with no quantities is how stock gets zeroed by accident.
Variant Barcode - the EAN/UPC. Watch Excel: it strips leading zeros and turns long barcodes into scientific notation unless the column is formatted as text.
Image Src - a publicly reachable image URL, one per row. Shopify downloads a copy on import; a URL that requires a login fails.
Variant Requires Shipping / Variant Taxable - the words true or false, lowercase. Not "yes", not 1.
Status - active, draft or archived.

The better starting point: your own export

The blank template has no examples, so every cell is a guess at the format Shopify wants. A real export of your own products (Products → Export) is the same file with the answers filled in: your handles, your option structure, your formats. Add new products by copying an existing product's rows and editing them, and the structure is right by construction. The column-mapping guide shows how to fit a supplier's spreadsheet into that shape without retyping it.

Rule: blank template for reference, real export for work.

Before you import it back

Two switches decide whether the import is safe. "Overwrite existing products that have the same handle" replaces matching values in existing products - and a blank non-required cell overwrites the existing value with blank. And any product in the file that already exists should be complete: all its variant and image rows, not a partial set. The common import errors are all variations on these two.
