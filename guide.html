Shopify CSV import errors that delete variants (and how to catch them first)

If you move supplier spreadsheets into Shopify, the dangerous mistakes are the quiet ones. The import finishes, nothing looks obviously wrong, and a week later you notice a product lost its variants or a price is wildly wrong. These are the errors worth checking before every import.

1. Missing option columns can delete variants

Shopify builds variants from the Option Name and Option Value columns under each product's Handle. Shopify's own documentation warns that when an import file includes a column that depends on other data the file leaves out - Shopify's example is a SKU column without the Option1 Name and Option1 Value columns - the existing data is deleted and the variant option is gone. It also warns that changing option values deletes existing variant IDs. In practice the dangerous file is the supplier sheet with one row per SKU and no option columns at all: import it over an existing product and its Size/Colour variants can be wiped.

Check: for every existing product in the file, confirm the option columns are present and every variant you sell still has a row.

2. Duplicate SKUs and repeated rows

Supplier files often list the same SKU twice: a restock line, a duplicated paste, two colourways merged badly. When two rows claim the same SKU it is ambiguous which values should win, and what lands in the store depends on the order the rows are processed.

Check: no SKU should appear twice in the file unless you know exactly why.

3. Decimal-comma prices ("19,99")

European suppliers often write prices with a decimal comma. Shopify expects a plain number like 19.99, and a comma is also the character that separates CSV columns, so an unquoted 19,99 can break the row's structure or be read as the wrong number depending on how the file is processed. Either way it needs a human decision before import, not an automatic conversion.

Check: any price containing a comma gets reviewed before the file goes anywhere near Shopify.

4. Prices that aren't numbers

"NZD 19.99", "POA", a currency symbol in the wrong place, or a formula that broke when the supplier exported. Shopify expects only the monetary value, without a currency symbol.

Check: every price cell is digits with at most one decimal point.

5. Unintended price and stock changes

If you import with "Overwrite products with matching handles" selected, Shopify replaces the values in the matching columns of existing products - and a blank non-required column overwrites the existing value with blank. A supplier file that quietly raises a cost, or leaves a field empty, will carry that change into your live store.

Check: compare the file against a current Shopify export and review every price and quantity change before import.

6. Barcode and boolean formatting

Excel strips leading zeros from EAN barcodes, and TRUE/FALSE columns arrive as "yes", "1", or "Y" while Shopify's CSV format expects true or false. Each one is small; together they make an import fail in ways that take an afternoon to untangle.

Check: barcodes keep their leading zeros and boolean columns read exactly true or false.
